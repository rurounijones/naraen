# naraen

Read @CONTRIBUTING.md for how to run the tooling and the project rules.

Whenever a design decision needs to be made, consult the project guidelines to determine which option is correct. If the guidelines settle it, follow them; if you still need user input, present the decision along with what the guidelines imply.

## Commits and pull requests

Follow the "Commit messages" section of @CONTRIBUTING.md for every commit you create and every PR title and description you write. In short: an imperative subject, then a wrapped body that explains why (problem and impact, approach, why this approach and the alternatives rejected, what was left out) rather than narrating the diff. Write the long body; do not shorten it to a one-liner when the change has a reason worth recording. Keep each commit to one logical change.
